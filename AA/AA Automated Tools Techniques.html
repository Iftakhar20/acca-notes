1. What Are Automated Tools & Techniques?

D5(a)
Modern clients store almost all their financial data electronically. Auditors use automated tools and techniques (ATT) to access, interrogate and analyse that data — rather than testing paper records manually.
Definition

Automated tools and techniques are computer-based methods used by auditors to obtain audit evidence. They allow large volumes of data to be tested quickly and consistently, helping the auditor form conclusions about controls and account balances.

There are three main types you must know:

Type 1

🖥️ Audit Software

Programs that interrogate the client's data to perform substantive tests. The auditor runs their own software against the client's live or copied files.

Substantive
Large populations
Type 2

🧪 Test Data

Dummy transactions input into the client's system to check whether programmed controls are working as expected.

Controls testing
Programmed controls
Type 3

📊 Data Analytics

Tools to analyse patterns, trends and anomalies across entire data sets — going beyond sampling to test 100% of transactions.

Risk assessment
Full population
🧠 Memory Hook

"Audit Software FINDS it. Test Data TESTS it. Data Analytics SPOTS it."

Audit Software → finds errors in the data. Test Data → tests whether controls catch bad inputs. Data Analytics → spots unusual patterns across all transactions.
🖥️

2. Audit Software — In Detail

D5(b)
What it does

Audit software is applied to the client's data files (usually a copy) to perform computations, select samples, identify exceptions, and run analytical checks — all automatically.

What Can Audit Software Do?

  • Cast (add up) ledger totals — e.g. verify the receivables ledger adds up correctly
  • Stratify data — e.g. split receivables into size bands (£0–£1k, £1k–£10k, over £10k)
  • Select samples — e.g. use monetary unit sampling to pick items for detailed testing
  • Recalculate figures — e.g. recompute depreciation or accruals across all assets
  • Age a balance — e.g. produce an aged receivables or payables analysis
  • Identify duplicates — e.g. flag duplicate invoice numbers in payables
  • Compare to limits — e.g. find receivables exceeding their credit limit
  • Trace and match — e.g. match purchase orders to GRNs to invoices (three-way match)
📋 Exam Example — Receivables (Delphic Co)
Audit software applied to the receivables ledger can: (1) cast the whole ledger, (2) compare each balance to its credit limit, (3) stratify balances and select a sample using MUS, and (4) produce an aged receivables analysis to identify potentially irrecoverable debts. All four are valid uses.
📋 Exam Example — Payables (Airsoft Co)
Where there is a risk of completeness of payables, audit software can: search for GRNs with no matching invoice (unrecorded liabilities), recalculate accruals for goods received not yet invoiced (GRNI), and calculate the payables payment period for use in analytical procedures.
📋 Exam Example — Inventory (Lily Window Glass Co)
For inventory, audit software can: (1) recalculate the cost of inventory by multiplying unit quantities by cost prices, (2) compare cost to net realisable value to flag NRV write-downs needed, (3) stratify inventory by value to select high-value items for testing, and (4) identify slow-moving inventory by comparing last-movement dates.
⚠️ Exam Trap

Test data is NOT the same as audit software. A common error is confusing them. Test data = dummy input into client's system to test controls. Audit software = the auditor's own program run against the client's data. If a question says "inputting dummy purchase invoices to see if processed correctly" — that is TEST DATA, not audit software.

3. Test Data — In Detail

D5(b)
What it does

The auditor creates fake (dummy) transactions and inputs them into the client's own IT system to see whether the programmed controls in that system work as intended.

How It Works — Step by Step

  • Step 1: Auditor creates both valid and deliberately invalid dummy transactions
  • Step 2: They are input into the client's live or parallel system
  • Step 3: The auditor checks: did the system accept valid ones and reject invalid ones?
  • Step 4: Results are compared to expected outcomes — any difference means a control failure

Examples of What Test Data Can Test

📋 Example — Sales System
Input a dummy sales order exceeding the customer's credit limit. The system should automatically block it. If it processes the order anyway, the credit limit control is failing.
📋 Example — Payroll System
Input a dummy payroll entry with a pay rate above the authorised maximum. The system should reject it. If it processes the payment, this shows the programmed payroll control is ineffective.
📋 Example — Purchases System (Lily Window Glass)
Input dummy purchase invoices with missing supplier codes, or duplicate invoice numbers, to check whether the system's validation controls flag and reject these as errors.
🧠 Quick Distinction

Test Data = "I put a fake transaction IN and watch what the system does."
Audit Software = "I take the real data OUT and analyse it myself."

Think of it like this: Test Data is like testing a smoke alarm with fake smoke. Audit Software is like reviewing the alarm log to see how many times it fired.

4. Data Analytics — In Detail

D5(b)
What it does

Data analytics tools allow auditors to analyse entire data sets (not just a sample) to identify patterns, trends, and anomalies. This provides deeper insight into risk and stronger evidence than traditional sampling alone.

What Data Analytics Can Do

  • Identify unusual transactions — e.g. sales transactions at unusual times (midnight sales) which may indicate fraud
  • Visualise trends — e.g. chart monthly revenue to spot seasonal anomalies or sudden spikes
  • Highlight outliers — e.g. a supplier paid at a rate far above all others
  • Test 100% of the population — rather than a sample, every transaction is reviewed
  • Correlate data sets — e.g. compare hours worked per employee to payroll payments to identify ghost employees
  • Benchmark against prior years — e.g. compare gross margin % month by month across two years
📋 Example — Revenue Testing
Using data analytics, the auditor can plot all 12 months of revenue and compare to prior year. Any month that looks unusual (e.g. December revenue 40% higher than the same month last year when no business reason exists) is flagged for further investigation — far quicker than manually reviewing invoices.
📋 Example — Payroll Fraud Detection
Analytics can compare the employee master file at the start of the year to the end of the year. Any employee added and removed within the same year, or any bank account receiving multiple pay transfers, can be automatically flagged — potentially identifying ghost employees.
📋 Example — Inventory (Lily Window Glass)
Analytics can identify all inventory items where the recorded quantity has not moved for more than 180 days — highlighting potentially obsolete stock requiring an NRV write-down. No manual review of hundreds of lines needed.
⚠️ Key Point for Exam

Data analytics is distinct from traditional audit software in that it focuses on pattern recognition and anomaly detection across 100% of data, rather than just recalculating or recasting numbers. Auditors still need professional judgement to interpret the results — the tool flags; the auditor concludes.

5. Benefits & Challenges — Full List

D5(c)

This is the highest-exam-frequency part of this topic. Both sides must be learned — questions ask for advantages and disadvantages together.

✅ Benefits / Advantages

  • Speed & efficiency — large volumes of data processed quickly, saving auditor time
  • 100% coverage — entire population tested rather than a sample, reducing sampling risk
  • Objectivity — the software applies the same rule to every item, no human inconsistency
  • Complex calculations — recalculations done accurately across thousands of records simultaneously
  • Better risk identification — data analytics can spot unusual patterns a manual review would miss
  • Ongoing/continuous auditing — data can be monitored throughout the year, not just at year end
  • Cost-effective long-term — once set up, software can be reused each year at minimal additional cost
  • Stratification and sampling — more precise sample selection reduces audit risk
  • Fraud detection — analytics can flag transactions inconsistent with normal patterns

❌ Challenges / Disadvantages

  • High setup costs — designing and configuring audit software can be expensive, especially for complex or old systems
  • Staff training — audit team must be trained to use the tools, which takes time and money
  • Systems compatibility — software may not work with the client's IT systems, especially older or bespoke systems
  • System documentation needed — auditor needs full documentation of the client's system; if unavailable, set-up fails
  • Client access restrictions — client may only provide copied files, not live access, limiting what can be tested
  • Data quality risk — if the client's data is incomplete or corrupted, results from automated tools will be unreliable (garbage in, garbage out)
  • System changes — if the client upgrades its system mid-year, the audit software may need to be completely redesigned
  • Test data risk (live system) — test data input into live systems must be completely reversed, or dummy entries may corrupt actual records
  • Slowing client systems — running audit software on client systems may slow down their operations
  • Professional judgement still needed — automated tools highlight anomalies but cannot reach audit conclusions
🧠 Exam Tip — Tailored Answers

In a scenario question, always tie advantages and disadvantages back to the specific company facts given.

E.g. If the client has 600 customers → advantage: audit software is highly efficient for large populations. If the client uses a 20-year-old bespoke system → disadvantage: compatibility issues and documentation may not be available. Generic lists alone will not score full marks.

7. Auditing Through vs Around the Computer

D5(a)

✅ Auditing THROUGH the Computer

Uses ATT — audit software or test data — to actually test the system and data inside the computer. The auditor gains direct evidence about what the system is doing.

  • Direct evidence of programmed controls operating
  • Can test 100% of transactions
  • More reliable for computer-dependent clients

⚠️ Auditing AROUND the Computer

Treating the computer as a "black box" — only testing inputs and outputs, ignoring what happens inside the system.

  • No direct evidence programs are working correctly
  • If errors found reconciling inputs to outputs, cause is unknown
  • Audit risk is higher — this approach is insufficient for complex IT systems
⚠️ Exam Question — Q126 Kaplan (Auditing Around)

Both statements are valid reasons why audit risk is HIGHER when auditing around: (1) actual programs are not tested so no direct evidence, and (2) if errors are found between inputs and outputs, it may be impossible to determine why they occurred.

8. Practice & Exam Application

D5 All
Practice — Classify the procedure

The auditor selects a sample of supplier balances using monetary unit sampling from the payables ledger. Is this: (A) Test Data, or (B) Audit Software?

Answer: (B) Audit Software. MUS sample selection is performed by running the auditor's software against the client's data — it does not involve inputting dummy transactions.
Practice — Classify the procedure

The auditor inputs a dummy purchase invoice with a missing purchase order number to see if the system blocks it. Is this: (A) Test Data, or (B) Audit Software?

Answer: (A) Test Data. This involves creating a fake (dummy) transaction and inputting it into the client's system to test whether a programmed control (requiring a valid PO number) works correctly.
Practice — Advantage in context

Delphic Co has over 600 customers. How does this fact support the use of audit software?

Answer: With 600 customers, manually reviewing every balance would be time-consuming and expensive. Audit software can cast the entire ledger, produce an aged analysis, stratify all balances, and select a statistically valid sample in minutes — the large population makes automation highly efficient and effective.
Practice — Disadvantage in context

Delphic Co uses old IT systems and full system documentation is not available. What disadvantage of audit software is relevant here?

Answer: Audit software must be configured specifically for the client's system. Without full documentation, it may be impossible or very costly to develop audit software that correctly reads and processes Delphic Co's files. The lack of documentation represents a significant practical obstacle to using automated tools.
Practice — 4-mark question style (Lily Window Glass)

Describe FOUR audit procedures for inventory that could be carried out using automated tools and techniques.

1. Audit Software — Valuation: Recalculate the cost of finished goods inventory by multiplying unit quantities per the inventory listing by unit cost prices, and compare to cost per the system to confirm accuracy.

2. Data Analytics — NRV: Compare recorded cost of each inventory line against current selling price to identify any items where cost exceeds NRV, flagging lines requiring a write-down.

3. Audit Software — Slow-moving: Filter inventory lines by last movement date to identify items not moved within the past 12 months, which may be obsolete and require a provision.

4. Test Data — Controls: Input a dummy inventory receipt with an invalid product code into the inventory system to test whether the system's validation controls reject unrecognised stock codes.
